Isaac Sim：仿真与渲染的交汇点

Isaac Sim 是 Omniverse 平台上专门针对机器人仿真和具身智能的应用。render-usd 选择它作为底座，不是偶然。

Isaac Sim 的定位

NVIDIA Isaac Sim 是一个 robotics simulation platform，但它同时也是一个一流的 RTX rendering engine。它的核心用户群是机器人学和具身智能研究者，需要：

  • 高保真物理仿真（PhysX）
  • 高保真实时渲染（RTX PathTracing / RayTracing）
  • 传感器模拟（Camera、Lidar、IMU、Force Sensor）
  • 大规模场景和资产库（SimReady assets）

render-usd 借用它的渲染能力，但跳过了物理仿真部分——我们的目标是出图，不是训练机器人走路。

World、Stage、Context 三件套

在 Isaac Sim 的 Python API 中，有三个概念你必须分清：

概念Python 对象类比作用
Worldomni.isaac.core.World物理世界 + 渲染循环管理 physics / rendering timestep，调用 world.step(render=True) 推进一帧
Stagepxr.Usd.Stage场景描述数据库USD 的场景图本身，存储 Prim、属性、关系、组合弧
Contextomni.usd.get_context()USD 文档管理器提供对当前 Stage 的访问入口，处理打开/保存/修改
From GAMES101
课堂渲染器没有 "World" 这个概念。你的渲染循环就是 for each pixel: trace_ray()。Isaac Sim 的 World 则是一个运行时引擎，它维护着物理状态、渲染状态、传感器状态的同步。你每调用一次 world.step(render=True)，它就完成一次「物理更新 + 渲染 + 传感器抓取」的完整周期。

为什么用 Isaac Sim 而不是 Blender / Unreal

这是一个合理的疑问。Blender 的 Cycles 渲染器非常出色，Unreal Engine 5 的 Lumen 也是顶尖实时 GI 方案。但 render-usd 选择 Isaac Sim 有几个工程上的理由：

  • 原生 USD 支持：Isaac Sim 的 runtime 就是 USD runtime，不需要导入/导出转换。Blender 的 USD IO 会丢失变体、材质绑定等信息。
  • Python-first API：所有功能都有 Python 绑定，适合自动化管线。Unreal 虽然有 Python 插件，但终究是 C++ 引擎的二次封装。
  • Sensor 生态：Isaac Sim 内置了 Camera、Lidar、Contact Sensor 等，且输出格式与机器人学工具链对齐。
  • Headless 渲染：Isaac Sim 可以在无 GUI 的服务器上跑 RTX PathTracing，这是批量 DLC 渲染的前提。
关键决策：render-usd 的架构与 Isaac Sim 深度耦合。这意味着你能获得最好的 USD 兼容性和传感器生态，但也意味着你必须理解 Isaac Sim 的启动顺序、资源生命周期和 crash 模式。
