GPU 资源清理：cleanup() 方法论

Python + GPU 的混合环境是内存泄漏的重灾区。render-usd 的 cleanup() 方法提供了一套可复用的资源释放模式。

Python GC 不知道 GPU 显存

Python 的 gc 模块只追踪 Python 对象之间的引用循环。它不知道一个 Camera 对象内部持有一个 CUDA framebuffer 指针。当 Camera 对象被 gc

cleanup() 的三层清理

  1. Annotator 清理：camera._custom_annotators.clear() 释放 Replicator 节点的 GPU 缓存
  2. Render Product 清理：camera._render_product = None 断开相机与 GPU framebuffer 的绑定
  3. World 重置：world.reset() 清除 USD imaging delegate 的缓存状态

周期性 gc.collect()

即使在正常运行中，render-usd 也会每 50 个资产强制一次垃圾回收：

renderer.py
if (idx_obj + 1) % 50 == 0:
    gc.collect()
    print(f"[Memory] Garbage collected after {idx_obj + 1} objects")

这不是过度谨慎。在 Isaac Sim 中，每个相机帧、每个 RGBA 数组、每个 BBox 结果都是 Python 对象。处理几千个资产时，这些对象的累积会显著增加内存压力，触发 OS 的 OOM killer 或导致性能下降。

Best Practice：在 GPU + Python 的混合环境中，永远不要依赖 Python 的自动 GC 来管理 GPU 资源。显式的 cleanup() 和定期的 gc.collect() 是生产代码的标配。
