Chunking：DLC 分布式渲染策略

五万个资产不能在一个进程里串行渲染。render-usd 通过 chunking 把任务切分成独立子任务，提交到 DLC（Deep Learning Container）集群并行执行。

Chunking 算法

cli.py (grscenes100)
total_assets = len(all_asset_usds)
chunk_size = (total_assets + args.chunk_total - 1) // args.chunk_total
start_idx = args.chunk_id * chunk_size
end_idx = min(start_idx + chunk_size, total_assets)
object_usd_paths = all_asset_usds[start_idx:end_idx]

(chunk_id, chunk_total) 是一对整数，把资产列表切成 chunk_total 个连续块。例如 52,907 个资产分成 100 个 chunk，每个 chunk 约 529 个资产。

为什么用连续切分而不是哈希

连续切分（contiguous chunking）的好处：

  • 磁盘局部性：同一 chunk 的资产通常在相近目录，共享的纹理/材质缓存命中率更高
  • 结果可预测：chunk 0 总是处理前 N 个资产，方便调试和重跑
  • 失败隔离：单个 chunk 失败只需重跑该 chunk，不影响其他 chunk 的结果

DLC 提交脚本

scripts/dlc/ 目录包含完整的提交工具链：

  • submit_batch.py：读取资产列表，生成 N 个 DLC job 配置
  • launch_job.sh：包装单条渲染命令，处理参数转发
  • run_task.sh：在 DLC 容器内执行，设置 PYTHONPATH 和 conda 环境
实际运行规模：2026-03-04 的 DLC Crash Fix 文档记录了一次真实提交：100 个 chunks，总计 52,907 个 USD 文件。修复后所有 chunks 均成功完成，exit code 0。
