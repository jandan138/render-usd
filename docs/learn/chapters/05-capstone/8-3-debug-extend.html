如何调试、扩展与贡献

你已经理解了 render-usd 的全貌。这一节提供实用的调试技巧和扩展思路。

调试 checklist

  • 全红：MDL 路径问题 → 检查 MDL_SYSTEM_PATH 和 --mdl_paths
  • 全黑：光照问题 → 检查 HDRI 是否加载、Intensity 是否为零
  • 全白：backgroundZeroAlpha 未开启 或 Intensity 过高
  • 特写/远景：BBox 异常 → 加日志打印 bbox_min, bbox_max, distance
  • segfault：GPU 资源泄漏 → 检查 cleanup() 和 shutdown 顺序
  • BBox 不显示：语义标签未设置 → 检查 add_update_semantics()

扩展思路

  • 增加视角：修改 sample_number 和 azimuth
  • 自定义背景色：修改 renderer.py 中 bg = np.full_like(..., 40, ...) 的 40 为任意值
  • 输出 Depth：在 setup_camera 中启用 with_distance=True，用 get_src(camera, "depth") 提取
  • 语义分割图：启用 with_semantic=True，输出每像素的类别 ID
  • 自适应 SPP：根据场景复杂度动态调整 world.step(render=True) 的帧数

贡献规范

项目使用 Agent-based development 工作流。任何修改都应附带：

  • 设计文档（docs/design/ 目录）
  • 异常处理（单个资产失败不中断批量任务）
  • 清理逻辑（新增的 GPU 资源必须在 cleanup() 中释放）
恭喜完成：你已经从 GAMES101 的 classroom renderer，走到了生产级 USD rendering pipeline 的核心。render-usd 的每一行代码现在都应该有了上下文和意义。
