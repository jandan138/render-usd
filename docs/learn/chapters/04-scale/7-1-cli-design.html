从单文件到批量：CLI 设计哲学

remder-usd 的 CLI 不是简单的「一个命令干所有」，而是分层设计：single → render_custom → grscenes → grscenes100，每一层对应不同的输入规模和目录结构。

四层命令结构

命令用途输入结构典型规模
single调试单文件单个 .usd 路径1
render_custom自定义目录批量渲染Category/UID/UID.usd100 ~ 1,000
grscenesGRScenes 数据集part{N}/{usd}_usd/{scene}/...1,000 ~ 10,000
grscenes100GRScenes-100 数据集 + DLC chunkingCategory/AssetID/AssetID.usd10,000 ~ 100,000

延迟导入（Lazy Import）

CLI 设计中的一个关键细节：

cli.py
# 先解析参数（不需要 Isaac Sim）
args = parser.parse_args()

# 再启动 Isaac Sim（ heavyweight 操作）
kit = SimulationApp(CONFIG)

# 最后才导入业务模块（必须在 SimulationApp 之后）
from render_usd.core.renderer import RenderManager

这种「先解析、再启动、最后导入」的顺序有两个好处：

  • 参数错误时快速退出，不需要等待 Isaac Sim 启动（~30-60 秒）
  • 避免在 Isaac Sim 环境未就绪时导入 omni.* 或 carb.* 导致 segfault

MDL 路径的三级收集

材质路径通过三级优先级合并，确保最大兼容性：

  1. CLI --mdl_paths：用户显式指定（最高优先级）
  2. MDL_SYSTEM_PATH 环境变量： colon-separated 路径列表
  3. DEFAULT_MDL_SEARCH_PATHS：代码中的默认路径（最低优先级）

所有路径经过 abspath 和 os.path.isdir 校验，不存在的目录自动过滤。
