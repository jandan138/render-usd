Carbonite (carb)：被忽略的「操作系统内核」

Carbonite 是 Omniverse 的「操作系统内核」。render-usd 中的 HDRI 透明背景和 MDL 路径修复，都要通过 carb.settings 完成。

一句话理解 Carbonite

如果把 Isaac Sim 比作一台电脑，Carbonite 就是 BIOS + 操作系统内核。它提供插件加载、配置管理、日志、事件、文件系统等基础设施。你写的 Python 代码运行在它的上层。

为什么 render-usd 必须了解 carb

因为 Isaac Sim 的几乎所有运行时配置都通过 carb.settings 管理。render-usd 在以下场景直接调用了 carb：

  • HDRI 透明背景（scene.py）：通过 carb.settings.set("/rtx/post/backgroundZeroAlpha/enabled", True) 启用背景透明。
  • MDL 材质路径注册（cli.py）：通过 carb.settings.set_string_array("/app/mdl/additionalSystemPaths", [...]) 告诉 MDL 编译器去哪找材质定义。
  • 渲染器参数：分辨率、采样数（SPP）、最大反弹次数等都可以通过 carb 动态调整。
From GAMES101
课堂渲染器的配置是硬编码的：const int WIDTH = 1024;。生产环境里，配置是层级化的键值对树，路径像 /rtx/pathtracing/spp，运行时可读写，且支持订阅变化回调。

carb.settings 核心用法

python
# ⚠️ 必须在 SimulationApp 初始化之后才能用！
from isaacsim import SimulationApp
app = SimulationApp({"headless": True})

import carb.settings
settings = carb.settings.get_settings()

# 读取
spp = settings.get("/rtx/pathtracing/spp")          # 每像素采样数
width = settings.get_as_int("/app/renderer/resolution/width")

# 写入
settings.set("/rtx/post/backgroundZeroAlpha/enabled", True)
settings.set_int("/rtx/pathtracing/spp", 64)
settings.set_string_array("/app/mdl/additionalSystemPaths", ["/path/to/mdl"])

# 监听变化
def on_change(item, event_type):
    if event_type == carb.settings.ChangeEventType.CHANGED:
        print("SPP changed to", settings.get("/rtx/pathtracing/spp"))

sub = settings.subscribe_to_node_change_events("/rtx/pathtracing/spp", on_change)

启动顺序：为什么 carb 必须在 SimulationApp 之后

这是新手最常踩的坑：

python
# ❌ 这会崩溃（Carbonite 运行时还不存在）
import carb.settings
settings = carb.settings.get_settings()   # <-- Segfault!

# ✅ 正确顺序
from isaacsim import SimulationApp
app = SimulationApp({"headless": True})   # <-- 初始化 Carbonite + Kit + 所有扩展

import carb.settings                      # <-- 现在 C++ 后端已经就绪
settings = carb.settings.get_settings()   # <-- 安全

SimulationApp() 内部会加载 libcarb.settings.plugin.so 等核心插件。在此之前，任何 carb.settings.get_settings() 调用都会因为底层 C++ 对象不存在而直接段错误。

工程铁律：在 render-usd 的 cli.py 中，所有 import carb 和 import omni 的代码都必须在 SimulationApp(CONFIG) 之后执行。这就是 cli.py 采用「先解析参数 → 再启动 Isaac Sim → 再 lazy import 业务模块」结构的原因。
