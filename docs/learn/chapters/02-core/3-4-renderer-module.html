Renderer 模块：Orchestration

renderer.py 是整个管线的指挥家。它不直接操作 GPU，而是通过调度 Scene 和 Camera 模块，完成「加载 → 摆相机 → 渲染 → 保存」的完整闭环。

RenderManager 的职责

  • 生命周期管理：创建 World、跟踪 Camera 列表、shutdown 时调用 cleanup()
  • 批量循环：遍历资产列表，对每个资产执行「reset → load prim → set pose → render → extract → save → delete prim」
  • 异常隔离：每个资产独立 try-except，单个失败不影响整个 job
  • 内存管理：每 50 个资产强制 gc.collect()

渲染循环的伪代码

renderer.py 核心循环 (概念)
for each asset_path in asset_list:
    world.reset()                    # 清除上一帧状态
    prim = create_prim("/World/Show", usd_path=asset_path)
    if prim is invalid: continue

    set_prim_cast_shadow_true(prim)
    add_update_semantics(prim, "instance", "class")
    bbox_min, bbox_max = compute_bbox(prim)
    if bbox has NaN/Inf: continue

    center = (bbox_min + bbox_max) / 2
    distance = norm(bbox_max - bbox_min) * 1.0
    distance = max(distance, 0.1)    # 防除零

    for i in range(4):
        azimuth = i * 90
        set_camera_look_at(cameras[i], center, azimuth=azimuth, elevation=35, distance=distance)

    for _ in range(100): world.step(render=False)   # 预热
    for _ in range(8):  world.step(render=True)     # 渲染收敛

    for i, camera in enumerate(cameras):
        rgba = get_src(camera, "rgba")
        rgb = alpha_composite(rgba, bg=(40,40,40))
        save_png(rgb, f"{name}_{i}.png")

    delete_prim("/World/Show")
    if idx % 50 == 0: gc.collect()

预热与收敛

注意循环里的两个 for：

  • 100 帧 render=False：预热（warm-up）。让 Isaac Sim 的渲染管线稳定，USD imaging delegate 完成所有数据的 GPU 上传。
  • 8 帧 render=True：PathTracing 收敛。每帧都是一次采样累积，8 帧足以让 thumbnail 级别的噪声降到可接受范围。
为什么需要预热？ Isaaac Sim 的渲染器是异步流水线。创建 Prim 后，USD 数据需要经过 Hydra 场景委托翻译到 GPU 的 BVH 和纹理内存。如果不预热直接抓取，可能拿到半初始化的画面。
