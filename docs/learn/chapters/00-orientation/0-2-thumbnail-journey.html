production rendering 全景：the thumbnail journey

一张 thumbnail 从原始资产到最终 PNG，要经历哪些阶段？我们把整条 pipeline 展开成一张地图。

Asset Journey 地图

想象你手里有一个家具 USD 资产——比如一张来自 GRScenes 数据集的床。它从磁盘上的一个 .usd 文件，变成四张标准视角的 thumbnail（front / left / back / right），要走过下面这段路：

USD File→ USD Stage→ Isaac Sim World→ HDRI Lighting→ Camera Pose→ RTX Render→ RGBA Extraction→ Alpha Composite→ PNG Output

Stage 1：USD 舞台搭建

USD 不是简单的 mesh 文件。它是一个场景图（scene graph）：有层级（hierarchy）、组合弧（composition arcs）、引用（references）、变体（variants）。你的床可能由 BedFrame.usd、Mattress.usd、Pillow.usd 组合而成，材质又引用外部的 .mdl 文件。

Isaac Sim 会把这个 USD 舞台加载进 OmniKit 的运行时，创建一个 World 对象。World 里不仅有你的床，还有物理状态、渲染状态、相机传感器——全部绑定在一起。

From GAMES101
在课堂渲染器里，「加载模型」就是读 .obj 到 vector<Triangle>。在 Isaac Sim 里，「加载模型」意味着构建一整个 USD Stage 的 runtime representation，包括材质编译、纹理上传、BVH 构建。

Stage 2：光照环境——从点光源到 HDRI

课堂渲染器里你可能放了一个点光源在 (5, 5, 5)，一个方向光从 (1, 1, 1) 照下来。这在 production 里远远不够——物体表面会过曝或欠曝，阴影硬得像剪纸，金属和玻璃完全没有环境反射。

HDRI (High Dynamic Range Image) 解决的是「真实环境光照」的问题。它是一张 360° 全景照片，记录了真实世界里每个方向的光照强度。把它贴在 DomeLight 内壁上，你的床就像被放进了真实摄影棚。

Stage 3：相机——从 LookAt 矩阵到物理传感器

在 GAMES101 里，相机就是两个矩阵：

$$ V = \text{LookAt}(eye, center, up), \quad P = \text{Perspective}(fov, aspect, near, far) $$

在 Isaac Sim 里，相机是一个物理传感器（sensor）。它有真实的光学参数：focal length（焦距）、aperture（孔径）、clipping range（裁剪平面）。更重要的是，它能挂载各种 annotator——不只是 RGB，还有 Depth、2D Bounding Box、3D Bounding Box、Semantic Segmentation、Motion Vector。

Stage 4：渲染与提取

RTX PathTracing 会追踪光线，考虑多次反弹、反射、折射。渲染完成后，Camera sensor 的 annotator 把数据从 GPU 显存读回 CPU 内存。我们拿到的是 RGBA 四通道图像——alpha 通道告诉我们哪些像素是物体、哪些像素是背景。

Stage 5：Alpha 合成——给物体换背景

因为我们用的是 HDRI DomeLight，背景会被 HDRI 的天空盒占据。如果不处理，你的床就躺在一片奇怪的树林里（取决于你用的 HDRI）。

backgroundZeroAlpha 是 RTX 的一个后处理开关：它把「没有击中任何物体的光线」的 alpha 设为 0。然后我们在 Python 里做 alpha compositing：

$$ \text{output} = \text{foreground} \times \alpha + \text{background} \times (1 - \alpha) $$

这样，白色物体就能在深灰色背景上清晰可见——这是解决「白色物体在白色背景上消失」的经典 trick。

一句话总结：thumbnail pipeline = 加载场景 + 打光 + 摆相机 + 渲染 + 抠图 + 换背景。render-usd 把这六步封装成了可配置、可批量、可容错的 Python 模块。
