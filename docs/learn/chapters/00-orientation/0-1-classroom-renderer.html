你的 GAMES101 渲染器到哪为止

在 GAMES101 里，你写过一个能画三角形、算光照、做 shadow mapping 的 software renderer。它很棒，但距离「给五万个 USD 资产批量出 thumbnail」还有多远？

GAMES101 教会了你什么

如果你完整地跟过 GAMES101（或任何一门基于 MITSuba / TinyRenderer 的图形学入门课），你的 mental model 里已经有了这些核心概念：

  • MVP 变换：Model → View → Projection，把三维顶点塞进 NDC（Normalized Device Coordinates）那个 [-1, 1]³ 的小盒子里。
  • Rasterization：用 Barycentric coordinates 判断像素是否在三角形内，做 Z-buffering 解决遮挡。
  • Shading：从 Blinn-Phong 到简单的 Path Tracing，你理解了 BRDF、Monte Carlo integration 和 Russian Roulette。
  • 数据结构：你用一个 struct Mesh { vector<Vector3f> vertices; vector<int> indices; } 就描述了整个世界。
From GAMES101
以上这些「第一性原理」在任何生产管线里都依然成立。不同的是，生产环境里没人从零开始写 rasterize_triangle()——你站在一堆成熟基础设施的肩膀上。

为什么 thumbnail 是个正经问题

你可能会问：不就是把模型摆好、拍四张照片吗？这值得写一个项目？

在 Embodied AI 和 VLM (Vision-Language Model) 的研究里，asset thumbnail 是下游任务的「视觉锚点」。如果批量渲染出的图光照不均、相机距离错误、背景把白色物体吞掉，VLM 的 grounding 精度会悄然下降——而你很难 debug 到是渲染管线的问题。

核心洞察：production rendering 的难点不在「算一张图」，而在「可靠地、可复现地、可扩展地算十万张图，且每张图的光照、相机、背景都一致」。
