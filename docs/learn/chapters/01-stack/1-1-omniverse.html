NVIDIA Omniverse 平台架构

Omniverse 不是某个软件，而是一个平台。理解它的层次结构，是理解 Isaac Sim 和 render-usd 的前提。

Omniverse 是什么

NVIDIA Omniverse 是一个面向 3D simulation 和 Digital Twin 的计算平台。它不是单一软件，而是一套基础设施：

  • USD (Universal Scene Description) 作为数据 backbone
  • Omniverse Kit 作为应用运行时框架
  • Carbonite (carb) 作为插件与配置内核
  • RTX renderer 作为内置光线追踪渲染器

课堂渲染器通常直接运行在操作系统之上，你的 main.cpp 就是顶层。Omniverse 则在 OS 和你的代码之间插入了五层抽象。这不是过度设计——每一层都解决了一个生产级问题：插件热加载、配置动态化、多渲染器共存、物理引擎解耦……

USD 作为 backbone 的意义

传统 3D 流程中，模型从 Maya 导出 .fbx，材质在 Substance 里做，动画在 Blender 里调，最后进 Unity/Unreal 还要再导一次。每过一次转换，信息就丢一层。

USD 的定位是「interchange format 的终极形态」：

  • 场景图（Scene Graph）：层级化的 Prim 树，不是扁平的 mesh 列表。
  • 组合（Composition）：通过 SubLayer、Reference、Payload 把多个文件组合成一个场景，而不需要复制数据。
  • 延迟加载（Lazy loading）：Payload 允许场景在内存里先占个位，真正需要渲染时才从磁盘加载。
  • 变体（Variants）：同一辆车的「红色版」和「蓝色版」可以共享 99% 的数据，只替换材质参数。

Kit 与扩展机制

Omniverse Kit 是整个平台的应用框架。Isaac Sim、USD Composer、Code 这些看起来完全不同的应用，底层都是同一个 kit.exe（或 kit 可执行文件），只是加载了不同的 扩展（extensions） 组合。

扩展是自描述的 .toml 包，包含 Python/C++ 代码、依赖声明、设置项。Kit 在启动时解析依赖图，按需加载扩展。这让 Omniverse 拥有极强的模块化能力——你可以只加载渲染相关的扩展，在 headless 服务器上跑纯批量渲染，而不需要启动完整的 GUI。
