USD Stage / Prim / Property 速成

USD 不是「另一种 3D 文件格式」，它是一个场景图数据库。理解 Stage、Prim、Property 的三层结构，是阅读 render-usd 源码的前提。

Stage：USD 的「文档」

Stage 是 USD 的顶层容器，类似于一个打开的数据库连接。你通过 Usd.Stage.Open(path) 打开一个 .usd 文件，得到一个 Stage 对象，然后在这个对象上查询、修改场景图。

python
from pxr import Usd
stage = Usd.Stage.Open("/path/to/asset.usd")
prim = stage.GetPrimAtPath("/Root/Instance")  # 按路径获取 Prim

Prim：场景图的「节点」

Prim 是 USD 场景图的基本单元。每个 Prim 有：

  • 路径（Path）：唯一的层级地址，如 /World/scene/Instances/Bed_01
  • 类型（Type）：如 Mesh、Xform、Camera、Material
  • 属性（Properties）：存储实际数据，如顶点坐标、变换矩阵、材质绑定
  • 子节点（Children）：形成树状层级

Property：Prim 的「字段」

Property 分为两类：

  • Attribute：有值的属性，如 points（顶点数组）、faceVertexIndices。通过 attr.Get() 读取。
  • Relationship：指向其他 Prim 路径的引用，如 binding:material 指向材质 Prim。通过 rel.GetTargets() 读取。
From GAMES101
你的 classroom renderer 里，mesh 数据结构可能是 struct Mesh { vector<vec3> vertices; vector<int> faces; }。USD 的 Mesh Prim 也存储同样的数据，但放在 points 和 faceVertexIndices 这两个 Attribute 里，并且多了层级、变换、材质绑定等生产级元数据。

Composition Arcs：USD 的超能力

USD 最强大的特性是组合（Composition）。多个 USD 文件可以通过 SubLayer、Reference、Payload、VariantSet 组合成一个逻辑场景，而不需要复制数据。

render-usd 中的 add_reference_to_stage(usd_path, prim_path) 就是 Reference 组合弧的简单应用：把外部 USD 文件引用到当前 Stage 的某个 Prim 路径下。
